# Sentinel: Decisions

- 2026-11-25: Project name stays "Sentinel". The clash with Microsoft Sentinel is accepted for a student portfolio project.
- 2026-11-25: The GitHub repo is private for now. Switch it to public before sharing the link on the CV.
- 2026-11-25: Claude merges each phase's pull request as soon as its GitHub checks pass, then pulls main. GitHub's built-in auto-merge is not available on a private repo on the free plan.
- 2026-11-25: The exfiltration scenario is stamped "just now" like every other scenario, not 3 AM as the plan says. New log lines stay at the top of the page, and the upload is detected by its size. An off-hours check stays on the README's "Next steps" list.
- 2026-11-25: Taste Skill is applied to the dashboard and Alerts pages too, alongside frontend-design. The plan had it on the public-facing pages only.
- 2026-11-25: GitHub work goes through the `gh` command-line tool. The GitHub plugin (an MCP server, a second way for Claude to reach GitHub) is switched off in the Claude Code user settings.
- 2026-11-25: UI polish pass after Phase 3, from a UI Design Review of every page at phone, tablet and desktop width. Fourteen fixes, same dark slate/teal theme: one teal focus ring everywhere, lighter red for error text, counts above the tables, headings that stay pinned while a table scrolls, shorter alert rows and alerts-first order on phones, one time format, a visible arrow on expandable log messages, tidier filter bars. The top-bar item "Rules" is renamed "Detections" (the address stays `#/rules`).
- 2026-11-25: The UXKIN reference library that ships with the UI Design Review plugin is not used. It was never signed in to.
- 2026-11-27: Phase 4 defaults chosen by Claude, for Mohamed to overrule if he disagrees. Demo mode is on whenever there is no API key, and `SENTINEL_DEMO=1` forces it. An alert is triaged the first time it is opened, then stored. Accepting or editing a suggestion never changes the alert's own severity, and the AI's original text is kept.
- 2026-11-27: The ten demo-mode answers were written by hand, because there is no API key yet. Replace them with live answers once there is one (on the README's "Next steps" list).
- 2026-11-27: Phase 5 defaults chosen by Claude, for Mohamed to overrule if he disagrees. Alerts are linked when they share a host or a user and are at most 30 minutes apart, and an incident is a chain of linked alerts. The mail gateway does not count as a shared host. An incident is Open while any of its alerts is New or In progress; it has no status of its own to set. Alerts closed as false positives stay on the timeline but are left out of the incident's severity and out of the report.
- 2026-11-27: The incidents table stores only the incident's number. The plan listed hosts, users, start time, end time and status as stored fields; they are worked out from the incident's alerts instead, so they cannot go out of date.
- 2026-11-27: Each incident gets an AI summary with the same Accept / Edit review as an alert's triage. The six demo-mode incident summaries were written by hand, like the triage answers. A summary is deleted when new alerts join its incident, even if the analyst had accepted it.
- 2026-11-27: The PDF report takes its executive summary and recommended steps from the incident summary (the analyst's version once reviewed). Addresses in it are defanged. PDFs are made only in Docker, because WeasyPrint needs system libraries that Windows lacks.
- 2026-11-27: On phones the top bar has no "Dashboard" link: the logo leads there and shows the underline. Five links do not fit a phone's width. On the incident page the timeline comes before the AI summary.
